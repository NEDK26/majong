# ADR 0001：按麻将语义分槽并分层识别牌面

- 状态：已采用
- 日期：2026-08-24

## 背景

旧 OCR 把轮廓窗口、暗牌张数和牌名置信度混在同一个评分中：同时枚举
`7/8/10/11/13/14` 等合法张数，再让平均模板分数选择结果。相邻牌框一旦粘连，
短窗口往往比完整 13/14 张得分更高，因此会长期停在“7 张，等待摸牌”。同一套
扁平特征还要直接区分 34 类；万子共有的大面积“萬”会压过上方数字，造成红五万、
二万/三万等系统性误判。实时层只确认“张数 + 分析模式”，没有逐牌跨帧共识，
所以许多稳定但单帧分差小的位置会一直显示不确定。

## 决策

### 1. 几何与分类彻底解耦

暗牌区域按以下不变量确定，不再让牌名分数参与张数选择：

1. 自己的暗牌从画面最左侧第一张直立牌开始；
2. 普通暗牌按近似固定水平步长连续排列；
3. 只有在 `3n+1` 张之后允许一次较大的间隔；间隔后的单张是摸入牌，随后结束；
4. 右侧更小、横置或距离更远的牌属于副露；
5. 自动模式只接受完整得到的合法暗牌张数；明确传入张数的紧裁静态图才允许等分
   后备。

主分割信号是亮色中性牌面的水平投影。外框轮廓可用于确定牌行高度和校准参考图，
但不再生成多个实战张数候选。

### 2. 牌面采用分层分类

每张牌先通过本地模板确定万、筒、索、字牌家族，再只在该家族内区分数字或字牌。
模板证据明确时直接保留；模板含糊且截图更接近雀魂训练风格时，才使用按家族训练的
线性一对一分类器。模板与模型一致会提高区分度；不一致时只有模型风格证据明显占优
才覆盖模板。

离线模型来自 Hugging Face 数据集 `pjura/mahjong_souls_tiles`（Apache-2.0）。
数据集图片角落含类别答案，预处理必须先移除角标。训练产物只保存线性权重和风格
原型；运行时不需要 PyTorch、Hugging Face 插件或网络。模型特征与模板特征都有显式
版本，版本变化会令旧缓存失效。

### 3. 实时结果逐牌跨帧融合

同一张数、槽位中心接近且大部分候选相容时，保留最近三帧。每个槽位累计第一候选
和备选分数；连续两帧一致可确认单帧小分差，第三帧的瞬时噪声不能覆盖多数结果。
张数变化、重新框选、切换显示器/张数、重新校准或导入样本时清空历史。牌理层仍需
连续两帧确认张数/状态变化，且跨帧后仍不可靠的牌不会产生舍牌建议。

## 被替代的方案

- 轮廓窗口枚举与 `shortlist`：会让短手牌子窗口击败完整手牌，已删除；
- 对特定位置或特定牌写条件分支：只能掩盖单张样本，不采用；
- 直接使用 ViT 模型：体积大、依赖重，而且数据角标会造成标签泄漏，不进入桌面包；
- 单纯降低不确定阈值：会把错误结果送入牌理分析，不采用。

## 验证约束

发布前至少覆盖：真实 13 张、真实 14 张与末尾摸牌间隔、红五万、最右二万、缺失
部分外框、副露后 8 张暗牌、横置单牌、模板缓存升级、重复低分帧确认、单帧噪声和
张数变化清空历史。真实截图必须与训练数据独立。
