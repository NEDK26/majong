# 立直麻将手牌分析工具

> 本程序仅用于立直麻将算法学习研究，禁止用于线上游戏对局辅助。
> 程序只处理用户提供的图片或本机框选的屏幕区域；不包含抓包、进程注入、
> 模拟点击、键盘控制或向外部服务上传画面。

## Windows 单文件 EXE

在仓库 [Releases](https://github.com/NEDK26/majong/releases) 下载
`MahjongStudyAnalyzer.exe`，无需安装 Python：

1. 首次使用时，把雀魂 34 种牌总览图直接拖到 EXE 文件上；看到“校准完成”后，
   模板会保存在当前 Windows 用户的本地数据目录；
2. 双击 EXE，只会在屏幕顶部显示一条 72px 高的原生提示条，不启动浏览器；
3. 首次点击“框选”，临时在游戏画面上拖框圈住自己的暗牌区域；
4. 之后提示条会持续显示当前向听、推荐舍牌、理论进张和识别置信度；
5. 只有点击“设置”时才会出现小型设置弹层，可切换显示器、暗牌张数以及
   DXGI/MSS 捕获方式。

Windows Defender 可能会对新发布、未签名的个人 EXE 显示信誉提示；可以先在
Release 页面核对来源。程序不会开放网页服务，也不会向公网传输截图。
Windows 默认优先使用 DXGI Desktop Duplication 捕获 Direct3D 游戏画面，失败时
自动退回 MSS；不读取游戏进程。GitHub Actions 会根据 `requirements.txt` 自动
下载依赖并打入 EXE，运行时不需要联网下载，也不需要安装 Python。

## 安装与运行

需要 Python 3.10 或更高版本。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

也可以直接传入手牌，或运行 3 组内置测试：

```bash
python main.py --hand 1m 2m 3m 1p 2p 3p 1s 2s 3s 7s 8s 9s 1z 9m
python main.py --demo
python -m unittest discover -s tests -v
```

## 本地图片 OCR

把图片裁到只保留自己的一行横向、正置暗牌，然后运行：

```bash
python main.py --ocr ./hand.png --ocr-count 14
```

有吃、碰、杠时，只识别可操作的暗牌，不把副露牌当作候选舍牌。暗牌合法
张数为 `13/14、10/11、7/8、4/5、1/2`；例如已经副露两组、摸牌后有 8 张
暗牌时使用：

```bash
python main.py --ocr ./open-hand.png --ocr-count 8
```

程序会先打印标准化识别结果和每张牌的置信度，再交给现有分析核心。保存带
检测框的调试图片：

```bash
python main.py --ocr ./hand.png --ocr-count 14 --ocr-debug ./ocr-debug.png
```

默认低于 `0.62` 的结果会停止，避免错误牌名直接进入分析。人工核对无误后可
使用 `--ocr-allow-low-confidence` 继续。OCR 只对传入的静态文件操作，不会
自动截屏或连接游戏。

默认牌图模板来自公共领域的
[FluffyStuff/riichi-mahjong-tiles](https://github.com/FluffyStuff/riichi-mahjong-tiles)。
模板匹配最适合电脑截图；实体牌照片、明显透视、遮挡或不同游戏皮肤可能需要
自定义模板。自定义模板目录通过 `--ocr-templates DIR` 指定，命名规则见
`assets/ocr_templates/README.md`。

### 把 34 种牌总览图逐张拆开

对于按“9 万+4 风、9 筒+3 元、9 索”排列的三行总览图，可以直接裁出
34 张以中文牌名命名的 PNG：

```bash
python split_mahjong_tiles.py ./麻将牌总览.png ./拆分结果 \
  --preview ./拆分检测预览.png
```

输出目录中会生成 `一万.png`～`九索.png`、`东.png`～`中.png`，以及一份
`牌名映射.json`。脚本默认保留牌顶的立体边；只需要白色正面时添加
`--top-padding 0`。默认不会覆盖已有同名图片；确认需要覆盖时添加 `--force`。

### 校准雀魂牌面

如果有雀魂“麻将牌”说明页（按 9 万+4 风、9 筒+3 元、9 索排列的 34 种牌
总览图），可以一次性生成本机专用模板：

```bash
python main.py --ocr-calibrate-mahjong-soul ./mahjong-soul-tile-guide.png
```

模板会保存到 `local_ocr_templates/mahjong_soul/`，之后运行 `--ocr` 会自动
优先使用。该目录已被 Git 忽略，雀魂参考图和裁出的素材不会上传到公开仓库。

如果总览图模板仍有误识别，可以在顶部条的“设置”中选择
“导入拆分好的牌 / 实战样本”。把实际游戏中裁出的单张牌图片放进同一文件夹，使用
`八筒.png`、`六索_2.png`、`北.png` 这样的中文文件名；同一种牌可以提供多张。
样本只保存在本机，不会上传到仓库或网络。

如果文件夹包含完整的34种中文命名单牌，它可以直接作为首次初始化模板，
无需再提供总览图。初始化时会为每种牌预生成正向、倒向、左横、右横特征，
顶部依次显示“一万已识别（1/34）”等进度；生成的特征缓存会在下次启动时复用。

### 本机诊断日志

识别结果不理想时，在顶部条的“设置”中点击“打开诊断文件夹”。程序会记录
捕获方式与耗时、OCR耗时、识别张数、每张牌的置信度及候选牌、自动修正结果、
框选坐标和完整异常。低置信度或自动修正发生时，会限频保存带编号检测框的
最近画面及同名 JSON；最多保留最近12组。日志和画面只保存在本机，不会上传。

## Windows 本地桌面研究客户端

桌面客户端只捕获你框选的屏幕区域。它不读取游戏进程、不抓包、不注入，
也不控制鼠标键盘、开放网页端口或发送网络请求。

首次使用：

1. 安装 Python 3.10 或更新版本，并勾选 **Add Python to PATH**；
2. 把雀魂 34 种牌总览图拖到 `calibrate_mahjong_soul.bat` 上完成本机校准；
3. 双击 `start_live_viewer.bat`，屏幕顶部会出现“牌理镜”提示条；
4. 点击“框选”，在临时出现的全屏画面上只圈住自己的暗牌。框选完成后
   全屏画面立即关闭，顶部条自动开始识别。

顶部条右侧只有“框选、暂停、设置、关闭”。显示器、暗牌张数、刷新间隔和
捕获方式都收在小型设置弹层里；区域与设置会保存在本机，下次启动自动恢复。

自动张数会把最右侧留有小间隔的摸入牌计入完整手牌，并保留 13/14、10/11
等各类合法张数候选。牌名置信度不足或前两名匹配过于接近时，实时界面会显示
“识别结果不稳定”，不会继续生成舍牌建议；张数或状态变化需连续两帧一致后
才会更新。重复导入相同的逐张模板会自动跳过，不再累积重复特征。

也可以从命令行启动：

```bat
.venv\Scripts\python.exe main.py --live
```

程序不监听网络端口。Windows 自动模式先用 DXGI 捕获 Direct3D 游戏画面，
失败时再用 MSS。若仍是黑屏，请在设置中强制切换捕获方式，并确认游戏与
牌理镜使用相同权限；游戏建议使用窗口化或无边框窗口。

## 关于闭门与副露后的张数

规则上，`3n+1` 张暗牌是等待摸牌状态，不能先舍牌；`3n+2` 张暗牌才会遍历
候选舍牌。闭门时对应 13/14 张；每有一组副露，暗牌张数减少 3。向听库会
把缺少的面子视为已经副露，并按以下规则排序：

1. 舍牌后的向听数越小越优先；
2. 向听数相同，理论有效进张总枚数越大越优先。

理论有效枚数按每种牌 4 枚减去当前手牌中的枚数计算，不扣除牌河、副露等
场上可见牌。分析同时考虑普通形、七对子与国士无双的最小向听数。

## OCR 与输入层的接口

OCR 模块输出标准化牌名列表，例如
`["1m", "2m", "3m", "2p", ...]`，然后调用：

```python
internal_hand = hand_input(ocr_output_tiles)
result = core_analyze(internal_hand)
```

输入层会负责格式校验和 34 数组转换，核心算法无需修改。
